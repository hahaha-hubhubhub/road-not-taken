## 1. 产品概述

### 1.1 一句话描述

用户说出一条自己没有走过的人生岔路，模型生成它不那么美好的真实版本，实体装置再通过翻转仪式和逐格热敏打印，让用户拿到一张“未选择人生小票”。

### 1.2 背景

人容易对没有做出的选择进行浪漫化：

- 如果当时去了另一座城市，也许会更自由。
- 如果当时接受了那份工作，也许已经成功。
- 如果当时没有分手，也许会一直幸福。

普通生成式产品通常顺着用户的想象继续美化。本项目反向使用模型能力：补齐这条路上的通勤、争吵、账单、失败、无聊与偶然，让“另一种人生”从滤镜中回到现实。

### 1.3 产品目标

- 在 2 分钟内完成一次有起承转合的互动。
- 让用户直观理解“没走的路不一定更好，只是未知”。
- 让模型负责个性化叙事与图像生成，让硬件负责不可替代的揭晓和实体结果。
- 形成适合现场围观、体验、拍照和带走的黑客松作品。

### 1.4 非目标

- 不预测用户真实未来。
- 不提供心理诊断、人生决策或投资建议。
- 不生成纯粹羞辱、恐吓或灾难化的内容。
- MVP 不追求开放世界模拟，也不追求长篇故事。

## 2. 核心概念

### 2.1 “丑化”定义

本项目中的“丑化”应理解为“去滤镜”，不是把结局一律写成悲剧。

模型需要：

- 承认那条路可能存在的吸引力。
- 补充被用户忽略的日常代价。
- 给出具体但不冒充事实的生活片段。
- 用荒诞、克制或黑色幽默收尾。
- 最终让用户感到释然、好笑或重新思考，而不是被攻击。

### 2.2 产品原则

1. **先诱惑，再拆解**：结果先呈现理想面，再逐步暴露代价。
2. **具体胜过说教**：用一顿冷掉的外卖、凌晨的末班车等细节代替大道理。
3. **硬件参与叙事**：没有实体装置，就无法获得完整的小票结果。
4. **明确是虚构**：所有结果均标注为模型生成的平行人生想象。
5. **轻量而有余味**：单次体验控制在 60-120 秒。

## 3. 目标用户与场景

### 3.1 目标用户

- 对某次选择仍有遗憾或好奇的人。
- 喜欢互动装置、AI 创作和轻量心理体验的人。
- 黑客松展台现场的体验者与围观者。

### 3.2 典型输入

- “如果我毕业后留在北京……”
- “如果我当时没有和他分手……”
- “如果我辞职去大理开咖啡店……”
- “如果我学的是美术而不是计算机……”

## 4. MVP 体验流程

### 4.1 主流程

1. **开始**
   用户在手机网页扫描展台二维码，看到一句输入提示：“说一条你没走过的路。”

2. **输入**
   用户使用文字或语音完成句式：“如果当时我 ______。”

3. **生成**
   服务端将输入交给模型，生成三幕式故事、三张单色插图及一条结尾文案。

4. **召唤**
   硬件灯光呼吸、播放短音效，屏幕或手机给出随机动作指令，例如“向左翻 1 次，再向右翻 2 次”。

5. **揭晓**
   设备用姿态传感器识别动作。每完成一段动作，热敏打印机打印一幕：
   - 第一幕：那条路最诱人的样子。
   - 第二幕：未被想象到的现实代价。
   - 第三幕：荒诞或意外的落点。

6. **收尾**
   小票最后打印免责声明、短句和二维码。手机同步显示完整结果，允许保存或分享。

### 4.2 示例结果

**输入**

> 如果当时我辞职去大理开咖啡店。

**第一幕：滤镜**

你在洱海边拥有了一扇总能照进晨光的窗，朋友们说你终于活成了自己。

**第二幕：代价**

旺季时你每天站十二小时，淡季时你学会用同一袋咖啡豆解释三种风味。房东第三次涨租那天，窗外的云依然很好看。

**第三幕：意外**

两年后店铺评分最高的产品不是咖啡，而是你为了补贴房租临时做的 Excel 经营模板。

**结尾**

> 另一条路也有风景，也要交房租。

## 5. 功能需求

### 5.1 手机端

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| WEB-01 | 支持输入 10-100 个字的“如果当时……” | P0 |
| WEB-02 | 支持语音转文字，失败时可改用键盘 | P1 |
| WEB-03 | 展示生成、等待硬件、动作完成和打印状态 | P0 |
| WEB-04 | 展示完整结果并支持保存长图 | P1 |
| WEB-05 | 每次体验使用短 session id 与硬件任务关联 | P0 |

### 5.2 模型服务

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| AI-01 | 输出固定结构的三幕故事与结尾短句 | P0 |
| AI-02 | 为每一幕生成适合黑白热敏打印的图像提示词 | P0 |
| AI-03 | 生成三张高对比、低细节、统一人物设定的图片 | P0 |
| AI-04 | 对自伤、疾病、犯罪等敏感输入进行安全改写或拒绝 | P0 |
| AI-05 | 总生成时间目标不超过 30 秒 | P1 |

模型输出应使用结构化 JSON，至少包含：

```json
{
  "title": "另一条路：大理",
  "scenes": [
    {
      "caption": "第一幕文案",
      "image_prompt": "单色漫画画面描述"
    }
  ],
  "ending": "结尾短句",
  "disclaimer": "这是模型生成的虚构故事，不是人生预测。"
}
```

| 编号 | 需求 | 优先级 |

| HW-01 | 打印服务连接设备网关，接收服务端下发的整张小票字节流 | P0 |
| HW-02 | 用震动与提示音反馈待机、生成、可互动、完成、故障状态（由手机端承担） | P0 |
| HW-03 | 用手机加速度计识别左右翻转，完成指定动作后才解锁打印 | P0 |
| HW-04 | 热敏打印三幕图文、结尾和二维码 | P0 |
| HW-05 | 提供重试或取消入口（页面按钮；实体按钮为可选项） | P1 |
| HW-06 | 用浏览器语音识别完成输入（Web Speech API） | P1 |
| HW-07 | ~~使用墨水屏逐帧预览生成结果~~ 本期不做 | — |

> **翻转的降级路径**：若手机传感器因时间或兼容性无法完成，可降级为页面按钮
> （§6.2 原本即允许此降级）。降级后打印门控不变——动作未完成前打印不会开始。

> 需要一个"准备好了，拿起手机"的确认步骤。

## 6. 硬件方案

### 6.1 推荐 MVP（B 路：笔记本驱动打印 + 手机传感器翻转）

- **打印主机**：笔记本，USB 连接 58mm 热敏打印机，运行打印服务——连接设备网关，把服务端下发的 ESC/POS 字节流写入打印机。
- **输入与显示**：手机浏览器，负责输入、三幕展示、结果与分享。
- **交互**：翻转动作由手机自身加速度计（`devicemotion`）识别；LED 与蜂鸣器降级为手机震动与提示音。
- **输出**：58mm 热敏打印机——核心交付物，不可替换。
- **外壳（可选）**：笔记本与打印机可装入外壳，仅露出票口，保留"装置"观感。

> 树莓派方案（Pi + IMU + LED）不再作为 MVP 路径：它需要额外采购、固件开发和现场看管一台
> dedicated 主机，而打印字节流契约不变意味着换主机不影响上游。若后续确需常开主机，
> 可在打印服务不变的前提下换回树莓派或 ESP32。

### 6.2 硬件不可替代性

热敏打印是核心输出，不是附加效果：

- 打印过程天然适合“逐帧揭晓”。
- 纸张只能向前输出，对应选择无法回退。
- 小票会随时间褪色，对应记忆和遗憾的消退。
- 用户能带走唯一实体副本，形成手机页面无法替代的体验。

若时间不足，动作识别可降级为实体旋钮或按钮，但打印不可取消。

## 7. 生成策略

### 7.1 故事结构

每次结果固定为三幕，降低模型漂移并控制打印长度：

1. **蜜月期**：满足用户对另一条路的最初想象。
2. **生活期**：加入至少两个具体、可信的成本。
3. **偏航期**：给出意外但不恶毒的结局。

### 7.2 内容边界

- 不把死亡、重病、残疾、贫困作为默认笑点。
- 不根据姓名、性别、地域等属性做歧视性推断。
- 不断言真实人物会出轨、犯罪或遭遇灾难。
- 涉及自伤或强烈心理危机时，不继续生成黑色幽默故事。
- 结尾不评价用户现在的人生是成功还是失败。

### 7.3 视觉风格

- 黑白、高对比、适合 58mm 热敏打印。
- 三格连环画或档案插图风格。
- 画面信息集中，避免大面积灰阶和细碎背景。
- 同一次生成中的人物、地点和服装保持一致。

## 8. 状态与异常

| 状态 | 手机端 | 硬件端 |
| --- | --- | --- |
| 待机 | 显示输入页 | 常亮或慢呼吸 |
| 生成中 | 显示进度文案 | 快呼吸、轻音效 |
| 待动作 | 显示翻转指令 | 指示灯提示方向 |
| 打印中 | 显示第几幕 | 逐幕打印 |
| 完成 | 展示保存与分享 | 完成音效 |
| 生成失败 | 允许重试或用预设结果 | 红灯短闪 |
| 断网 | 切换演示模式 | 打印预生成内容 |
| 缺纸/卡纸 | 提示工作人员 | 红灯常亮并停止任务 |

## 9. 成功指标

黑客松现场重点验证：

- 80% 以上体验者能独立完成输入、动作和取票。
- 从提交到开始打印的中位时间不超过 30 秒。
- 单次完整体验不超过 2 分钟。
- 连续演示 20 次，无需重启服务或手动恢复设备。
- 体验后用户能用一句话说出“另一条路也有代价”的核心表达。

## 10. MVP 验收标准

- 输入任意合规的“如果当时……”后，能稳定得到三幕结构化结果。
- 三幕内容由理想到现实逐步转折，不是无差别悲剧。
- 用户未完成硬件动作时，打印不会开始。
- 完成动作后，设备能按顺序打印三幕图文与二维码。
- 断网或模型超时时，可在 10 秒内切换到预生成演示案例。
- 所有结果均包含“虚构内容，非人生预测”声明。

## 11. 技术架构

```text
手机浏览器（web/，纯静态）
   │  POST /api/sessions             创建 session
   │  POST /api/sessions/:id/generate  提交“如果当时……”
   │  GET  /api/sessions/:id         轮询状态
   ▼
应用服务（server/，Node + TypeScript）
   ├── LLM 层：StepFun step-5-preview，JSON Schema 严格结构化输出
   │      → 三幕故事 + 三张画面提示词 + 结尾短句
   ├── 会话状态机：created → generating → await_action → printing → done / error
   ├── 打印排版：PNG → 1-bit 抖动 → ESC/POS 字节流（含二维码）
   └── 设备网关：WebSocket /device
            │  task（含整张小票字节流）/ action_required / print_authorized / cancel
            ▼
       打印服务（笔记本 + USB 58mm 热敏打印机）
            硬件未到位期间由 npm run mock-device 模拟，行为与真机一致
```

架构原则与全部接口契约（REST API、设备协议、打印管线、实测延迟）见
[ARCHITECTURE.md](ARCHITECTURE.md)。

关键设计：**服务端完成全部排版与位图转换，打印侧只负责把字节流写进打印机**，
联调复杂度留在软件侧。这条边界已经落地，因此打印主机可以在笔记本、树莓派、
ESP32 之间替换，上游模块一律不用改。

## 12. 开发阶段

### 阶段一：闭环优先 —— ✅ 已完成（2026-10-11）

- 文本输入、三幕文本生成、按钮触发打印。
- 使用预制图片验证热敏打印效果。
- 实际交付超出原计划：设备协议、模拟设备、打印门控、演示模式、静态托管、浏览器端到端验证。

### 阶段二：硬件交互（B 路）—— 进行中

- 实现打印服务：连接设备网关，把下发的小票字节流写入 USB 热敏打印机。
- 用手机加速度计识别翻转，接入 `action_progress` / `action_complete`。
- 用手机震动与提示音映射五种状态（HW-02）。
- 缺纸/卡纸检测与 `error` 上报（HW-05）。
- （可选）笔记本与打印机装入外壳。

### 阶段三：图像与体验

- 接入图片生成模型，替换预置插画（AI-03），保持同一人物设定。
- 打磨提示词、动效、声音与容错流程。

### 阶段四：演示保障

- 预生成案例已内置 4 个，按需补足到 5-10 个。
- 连续压力测试（20 次不断流）、缺纸测试、断网测试和超时测试。

## 13. 决策记录

v0.2 起，原「待团队确认」的三项已全部有结论：

| 原问题 | 结论 |
| --- | --- |
| MVP 是否由手机输入，还是必须直接对硬件说话 | **手机输入**。手机负责输入与展示，硬件只负责仪式与最终交付。 |
| 硬件形态是可拿起翻转的物体，还是固定桌面装置加旋钮 | **B 路**：笔记本驱动打印 + 手机传感器翻转。树莓派 + IMU + LED 不再作为 MVP 路径；翻转可降级为页面按钮。 |
| 图像生成速度不足时，是否接受“预制插画 + 模型选图/改文案”的降级方案 | **接受降级**。插画先用预置线描图，接入点（`presetImageBitmap()`）已留好。 |
