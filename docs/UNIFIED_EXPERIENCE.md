# 统一后悔药体验

## 功能迁移

| 原版功能 | 统一体验 |
| --- | --- |
| 模型 Key / Base URL / 模型 / 生图模型 | 顶栏设置，模型使用自由输入，留空使用服务器配置 |
| 服务地址 | 设置高级连接项；不自动继承旧 api 参数作为密钥目的地 |
| 输入、语音、案例灵感 | 药丸后的输入页，支持 1000 字；灵感只填入，不自动生成 |
| session 轮询 | 单次递归轮询，取消/重试防止迟到结果污染新体验 |
| 翻转感应 | 沿用原检测器，手机实际翻转逐步上报，无硬件时提供明确模拟按钮 |
| 实体设备、打印、胶囊出仓 | 原状态机与协议不变，界面区分 receipt / capsule / demo |
| 三幕插画 | 已生成的幕使用真实图片，其余预置；后台补图不打断阅读 |
| 小票 | 来信后的带走页，保留短 caption 与二维码 |
| 保存 | 来信文本与按实际高度生成的完整故事长图（含详细三幕和信） |
| 分享 | 旧 #/r/id 可回看同一体验；只读回看不会取消原任务 |
| 危机输入 | 不下发设备、不打印、不提供分享 |

新增保留：药瓶、摇一摇掉药、三幕具体标题/正文、最后揭晓来信。

## 明确状态

生成失败的预写案例等待 `await_demo`，用户接受后才进入 `await_action`；显式服务器演示模式可直接继续。翻转全部完成才授权打印；真实胶囊必须等待设备确认，不能拿模拟计时器当真机证据。无设备的打印/封装明确标注模拟。

生图依赖服务端 IMAGE_API_KEY，不把用户浏览器里的文本 Key 自动复制为生图 Key。本机已将用户授权使用的模型工具 Key 配入被 Git 忽略的 .env；其他协作者仍需自行配置。原始输入不进入分享视图；故事和信可由链接持有人访问，24 小时 TTL，服务重启即丢失内存结果。

## 验证范围

构建、生成质量替身、统一状态/公开字段回归、原胶囊越权/危机/故障协议回归，及浏览器药瓶→输入→生成→解锁→交付→三幕→信→小票→分享→重新开始。真实机械卷纸、封装与出仓仍需真机验证；浏览器语音和手机传感器取决于设备支持与权限。

验证记录：8 项 Node 检查通过；胶囊协议模拟正向、越权、危机和卡纸回归通过。真实模型在统一 session 流程生成了修自行车的三幕与信，浏览器完成模拟交付、逐幕阅读、拆信、小票、复制链接与只读分享回看。手机 390×844 布局检查通过。

本机同一模型服务的真实生图调用验证：三幕插画均成功返回并完成打印图转换，单幕约 36 秒；新增下载链接供手机浏览器未自动保存时手动下载。浏览器内已验证长图准备完成，内置浏览器下载工具未返回落盘路径。
