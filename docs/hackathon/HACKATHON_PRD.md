# 后悔药 - Road Not Taken

**黑客松对外展示文档 · v1.0**
2026-10-16 · 孔令楠、赵澜卜、余靓、王涵末、凯撒

## 这是个什么东西

你说出一条你没走的路。AI 不顺着你往下美化，而是给它拆滤镜：先承认那条路确实诱人，再补上你没想到的账单、通勤和争吵，最后落在一个不太好笑的笑话上。

这段话会被打印在 58mm 热敏纸上。按最终设计，纸带会被卷起来、封进一颗**不能吃的展示胶囊**，从一台小机器里吐出来给你带走。胶囊机构还在打样，现场先交付小票，但流程、协议、软件全是真的。

项目名借自 Robert Frost 那首《未选择的路》。那首诗被当成励志诗读了几十年，诗人自己却说它 "tricky"：两条路差别没多大，所谓"一切都因此不同"，恰恰因为你永远无法回头验证。我们做的，就是把这种无法验证摊开给人看。

## 为什么做这个

人对没选过的路有个通病：自动美化。

"如果当时留在了那座城市""如果当时接了那个 offer""如果当时没分手"。这些话一开头，结局往往已经替自己安排好了：更自由、更成功、更幸福。可惜这些结局一个都没被验证过，也没法验证。

现在的大多数 AI 产品选择配合这种想象：你说"如果当时"，它帮你续写圆满人生，皆大欢喜。我们想反过来用这个能力：让模型当那个拆台的人，把"另一种人生"从滤镜里拽回地面。另一条路当然有风景，但它也要交房租。

顺带说清楚我们不做什么：不预测你的真实未来，不做心理诊断或人生建议，不评判你现在的生活是成功还是失败。生成的一切都标注为虚构。

## 现场体验走一遍

**1. 扫码，领一颗后悔药。** 手机打开页面，屏幕上摆着一只药瓶。摇一摇，掉出一颗胶囊；再摇一下，胶囊打开，进入输入。点当然也可以，传感器不灵的时候，永远有点击兜底。

**2. 说一条没走的路。** 标题就是半句话："如果当时我……"。占位符写着"去了另一座城市，学了自己喜欢的专业，或者，把那句话说出口"。打字或语音，最多 1000 字。按钮叫"吞下这颗后悔药"。

**3. 等它写。** 一般 30 秒到一分半。这段时间模型同时干三件事：把三幕故事写出来（滤镜 / 代价 / 意外），给另一条时间线的"你自己"起草一封信，并行画三张热敏质感的插画。

**4. 翻手机解锁。** 页面请你把手机屏幕朝下，停大约 0.65 秒再翻回来。翻转是仪式，不是噱头：先完成动作，才允许打印。这个门控写在服务端，模拟器和真机走同一套逻辑，绕不过去。

**5. 出票。** 三幕、三张图、一句结尾、二维码，打印成一张小票。没接真机时页面会明确写着"正在模拟打印，不会出实体小票"，不装。

**6. 读信。** 小票之外，手机上还有一封没拆的信。拆开，是另一条时间线上的你写来的，120 到 220 字，回扣你故事里的两个具体细节。写到这里，身份才揭晓。

**7. 带走或分享。** 信和完整故事可以存成长图。分享链接 24 小时后失效，且**不包含你的原文**，你的遗憾不该跟着链接跑。

还有一条暗线：危机输入（比如"不想活了"）走完全另一条路。手机上只有安抚文案和退出入口，不打印、不出胶囊、不分享。这是安全底线，不是功能。

## 技术上的一些事

服务端 Node 26 + TypeScript + Express + ws；前端零依赖纯静态，手机扫码即用，没有构建步骤。

模型用 StepFun step-5-preview，靠 `json_schema` + `strict:true` 做 API 级结构化输出，zod 再校验一遍，失败重试一次，然后降级到预生成案例。断网和超时立即降级，演示不能中断；但降级内容必须在纸面上能看出来是降级，不拿预生成冒充实时生成。实测从提交到出票 33 到 47 秒。

打印链路：PNG → Floyd–Steinberg 抖动成 1-bit → ESC/POS 光栅位图，连同 GBK 文本和二维码，整张小票排成一条字节流下发。打印侧只负责把字节流写进打印机。所以打印主机用笔记本、树莓派还是 ESP32，上游一行都不用改。我们因此把 MVP 的树莓派方案换成了笔记本 + 手机传感器，省下的不只是钱。

还有一笔没还的账：公网开放前要补设备鉴权和访问控制，现在的本地服务不满足这些条件，所以它现在还待在局域网里。

## 我们改过的几个主意

**树莓派不做了。** 原方案是 Pi + IMU + LED 全套。后来算过一笔账：打印字节流契约不变，换主机不影响上游，而现场看管一台 dedicated 主机的成本比每人一部手机高得多。交互和反馈全部移回手机。

**生图改成"先发预置图，再替换"。** 三张图并行要 30 多秒，等图齐了再下发，出票时间会从 33 秒涨到 60 秒以上。而用户翻转手机本来就要几秒，这段等待正好被用户动作覆盖。图就绪后用同一条任务消息替换内容，打印授权到达时用最新版本。

**翻转和打印解耦。** 最早想的是"边翻边打印"，跟"整张票一条字节流"的架构直接冲突，还会增加卡纸风险。改成动作全部完成才授权打印。

**小票必须带生成图。** 中途一度改成"图上手机、纸面用预置图"，被我们自己推翻了：小票的核心是可带走的实体纪念物，图是其中一部分，只出现在屏幕上就削弱了实物的完整性。

## 踩过的坑

`max_tokens` 一开始给 1600，正文被截断，偶尔整篇返回空。排查半天才发现，这个模型的思考过程计入 completion_tokens。有一次光思考就吃了 3500 多个 token，重试后总耗时 77 秒。默认值改到 8000，截断时自动加额重试，上限 12000。

有个 bug 只在浏览器里出得来：服务端冒烟测试全绿，页面却显示"未连接本地服务"。根因是前端拼 URL 少了 `/api` 前缀，请求打到 `/health` 返回 404。教训很直白：服务端测试全绿不等于前端能连通。

所以浏览器验证也不能再用 `--dump-dom`：它在页面 load 后就地 dump，等不到异步生成，会把降级路径误判成主路径通过。换成了基于 Chrome DevTools Protocol 的检查脚本，真的等生成完，再断言三幕标签、二维码和"没有降级标记"。

## 接下来

机械台架先跑空白条 20 次、文字内芯 20 次，故障注入（盖开、堵塞、缺胶囊、断线）各 3 次。0 次夹手、20/20 交付且不需要人工复位，才敢谈展台无人值守。在那之前，分享默认关闭、危机输入不打印，这两条不动。

*一行总结：你写一个"如果当时"，AI 负责拆滤镜，打印机负责让你带走，而胶囊还在路上。*
