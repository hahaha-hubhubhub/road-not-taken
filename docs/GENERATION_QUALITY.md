# 个性化生成与多样性

药丸页入口：`/regret-remedy/`。先在原首页 `/` 的设置中配置文本模型，或使用服务端环境变量。此页只调用同源 `/api/stories/preview`，不创建硬件会话、不触发打印、不保存用户输入；浏览器重启或重新开始后不保存上次原文。

## 文案风格

以用户提供的生活对白为节奏参考：短句、问答、动作，话里有具体的取舍。情绪不由旁白解释，也不把每句话写成金句。`heading` 是每幕 2-28 字的具体对白或动作，药丸页优先显示这个标题；旧演示结果仍可使用原来的标题回退。

用户参考中的铺子、肉、账本、规矩只属于参考场景，不能硬套到感情、学习和其他用户选择。人物自己的做法不等于给用户下处方，故事不保证善良必定成功。信也采用自然口语、短段落，回扣具体故事，不突然转成鸡汤。

## 输出与质量门槛

- 三幕仍保持滤镜、代价、意外的连续结构。`caption` 是 8-60 字打印文案；`detail` 是手机端 70-140 字的具体故事，最多 220 字，保留既有打印结构。
- `letter` 是另一条时间线的自己写给用户的来信，目标 120-220 字，回扣前面两个具体细节。只有拆信阶段揭晓身份。
- `anchors` 提取用户原文中的具体信息。校验来自原文、在正文或信中出现、不是空词；不满足时重试。该规则只能校验文字落点，不能证明因果、否定关系和感情完全理解正确。
- 每次请求随机选取切入点、时间节奏和语气，共 36 种组合。重试沿用同一方向；多样性不等于保证每次故事不同，也不通过随机改变用户选择制造差异。
- 去掉会让模型照抄的完整故事示例，避免每个职业都落到房租、加班、外卖。
- 服务端与页面区分真实生成、关怀回应和演示。降级后必须主动选择查看演示；未知主题使用明确标注的通用演示，不再按哈希挑一个不相关案例。
- 真实生成失败时保留输入，支持重试。重新开始会取消页面请求，忽略过期返回结果；已发出的模型计算不保证能被取消。

## 已验证与未验证

`cd server && npm run test:story-quality`：使用本地模型替身验证新旧 Schema 兼容、捏造锚点拒绝、重复幕拒绝、演示匹配、长输入、危机路由和自动重试。

浏览器验证：药瓶、药丸、提交请求、显式演示选择、三幕、拆信、重新开始；服务端预览 API 的演示标识、关怀路由与输入上限。

2026-10-13 本机从现有模型工具配置接入文本模型，密钥仅保存在被 Git 忽略的本地 `.env` 中，不上传。真实调用发现模型可能将锚点换成同义说法而未通过逐字校验；提示词增加输出前核对，重试反馈明确指出缺失的具体锚点。单次连通测试不能代表相关性、多样性和安慰感已完成评测，仍需下面的多组验收。

## 真实模型验收建议

对以下输入各生成 3 次，保存结果与耗时。不要只比较随机方向或温度；人工分别检查选择是否正确、细节是否由选择产生、三幕是否连续、信是否回扣情节，同一输入的三次是否在事件/对话/物件上有实质变化。

1. 如果当时没有学计算机，而是去上海学设计，我想做自己的作品，但又舍不得家里。
2. 如果当时没有和他分手，我们都不太会表达，我想知道能不能学会好好相处。
3. 如果当时和他分手而不是留下，我最舍不得的是一起养的猫。
4. 如果我去了巴黎学建筑，没有多少钱，而且不太会法语。
5. 如果我留在县城照顾家人，而不是去北京，我想知道是否还能做喜欢的工作。
6. 如果当时辞职去大理开咖啡店，我喜欢做甜点，但害怕每天都必须和客人聊天。
7. 如果我当时只是把那句道歉说出口，没有想过要重新在一起。
8. 如果我选了稳定的工作而不是创业，我怕的是再也没有自己的时间。

不合格表现：颠倒“没有分手/分手”；改城市或专业；只复制输入到标题；每篇都有同样账单结尾；突然安排婚姻、孩子或灾难；来信只有通用鸡汤；强行宣布原来的选择最好。上线前用实际模型完成这组评测再判断改善幅度。
