# 没走的路 / Road Not Taken

一个结合生成式模型与实体装置的黑客松项目。**目前胶囊仅完成软件协议与模拟器，实体卷纸/封壳/出仓尚未验证。**

人们常把没有选择的人生想象得更美好。用户说出一句“如果当时……”，模型不会继续美化那条路，而是生成一段具体、克制、带有代价的平行人生。实体设备完成解锁后，计划将精简的故事文字打印、卷起并封入一枚**不可吞食的展示胶囊**。旧设备仍可打印完整小票；胶囊机构还在打样阶段。

## 核心体验

1. 用户输入或说出一个未实现的选择。
2. 模型生成一条“去滤镜”的平行人生，包括诱惑、现实代价和意外结局。
3. 计划由设备灯光/音效提示翻转动作（当前用模拟设备验证协议）。
4. 完成全部动作后，胶囊设备打印文字内芯，完成卷纸/封壳/出仓后才显示完成；无硬件时仅模拟。
5. 用户取走展示胶囊（非药品、不可吞食）；旧设备交付小票。手机展示完整三幕，分享和隐私策略仍待上线前完善。

## 为什么需要硬件

硬件不是手机页面的遥控器，而是作品的叙事媒介：

- 翻转设备对应“翻转一次选择”。
- 完成动作后打印、封装和出仓的过程，制造不可跳过的揭晓仪式。
- 热敏纸带与非食用胶囊把一次模型生成变成可触摸、会褪色的纪念物；机械闭环还需证实。
- 手机负责输入和完整结果；实体设备负责仪式与最终交付。分享默认私密的改造仍是公开演示前的阻断项。

## 快速开始（本地）

```bash
cp .env.example .env        # 密钥可以先不填
cd server && npm install
npm start                   #  http://localhost:8787
```

打开页面后**点右上角「设置」填入 StepFun API Key**（只保存在这台设备的浏览器里，
生成时随请求头发给本地服务端），即可直接使用。也可以在 `.env` 里配 `STEPFUN_API_KEY`，
两种方式可并存，**页面设置的 Key 优先**。

```bash
cd server
npm run mock-device         # 可选：模拟设备；默认不保存用户内容（--save-receipt 调试才落盘）
npm run smoke               # 两条软件路径端到端（测试 Key / MOCK_LLM）
npm run capsule-check       # 需要 MOCK_LLM=1 服务端；封装门控/危机/卡纸回归
npm run browser-check       # 真实浏览器端到端（CDP，会等生成完成）
npm run try-llm -- "如果我当时……" low 4000   # 调试 prompt 与耗时（默认配置，实测最快且完整）
```

手机连接有两种方式，**翻转手势只能用第一种**：

1. **USB + `adb reverse`（推荐，翻转手势必须用这种）**

   ```bash
   adb reverse tcp:8787 tcp:8787
   ```

   手机浏览器打开 `http://localhost:8787`。

2. **同一 Wi-Fi 访问日志里的局域网地址**（如 `http://10.x.x.x:8787`）

   页面能打开、能输入、能看结果，但**翻转手势会失效**。浏览器只在安全上下文
   （`https://` 或 `http://localhost`）下允许读取 `deviceorientation`，局域网 IP
   不在其中，且失败是静默的——看起来像功能坏了。这种方式只适合验证按钮路径。

没有实体设备时页面会提供「我完成了翻转（演示）」按钮，与真机走同一套状态机和打印门控。

## 当前状态

原小票软件闭环已跑通；本轮增加了**文字内芯 → 封装授权 → 出仓确认**的模拟链路。
设备 `hello` 声明 capsule 能力才会收到胶囊任务；旧设备仍按小票交付。
这不等于真实硬件已经可用：切刀、卷纸、封壳、出仓传感器和机械互锁都待采购/打样/压力测试。

## 统一后悔药体验

现在只有一个首页 `/`，旧地址 `/regret-remedy/` 会跳转到同一体验，保留查询参数与分享链接。

流程：摇一摇或点药瓶 → 点药丸 → 输入/语音 → 真实三幕生成 → 手机翻转解锁 → 打印与封装（无硬件明确模拟）→ 逐幕阅读 → 拆开另一时间线来信 → 保存信、故事长图或分享二维码。

设置位于右上角：API Key、任意文本模型名、模型 Base URL、插画模型和可选项目服务地址。浏览器设置优先，留空使用服务端 `.env`。插画 Key 仍只从服务端配置读取；未启用或生成失败时显示预置插画，不把它标成 AI 生成。

主页面使用原有 `/api/sessions` 状态机，详细正文与来信随结果返回；打印仍用短 caption。生成降级会停在 `await_demo`，用户明确接受后才下发设备。服务端显式 `MOCK_LLM=1` 仍可直接跑协议回归。取消会停止当前物理任务并丢弃迟到的生成结果，完成的分享结果不被回看页面的重新开始取消。

结果分享默认保留 24 小时，不包含输入原文；链接持有人可访问虚构故事和来信。`PUBLIC_WEB_URL` 应设置成分享接收者可访问的地址；本机 localhost 链接需要 USB 转接或同一服务，不能当成公网链接。

前端代码：`web/regret-remedy/`；原版的 `web/app.js` 与 `web/styles.css` 已移除，翻转检测仍复用 `web/flip.js`。静态托管时根 index 只负责跳转，仍需连接项目服务。

参见 [生成质量与手机互动](docs/GENERATION_QUALITY.md) 和 [统一体验功能核对](docs/UNIFIED_EXPERIENCE.md)。
